How is this calculated?

Scoring (FanDuel's standard rules) — passing {{ methodology.scoring.pass_yd }} pt/yd, {{ methodology.scoring.pass_td }} pt/TD, {{ methodology.scoring.pass_int }} pt/INT; rushing & receiving {{ methodology.scoring.rush_yd }} pt/yd, {{ methodology.scoring.rush_td }} pt/TD, {{ methodology.scoring.reception }} pt/reception; fumbles lost {{ methodology.scoring.fumble_lost }} pts; return TDs {{ methodology.scoring.return_td }} pts. Team DST: {{ methodology.scoring.dst_sack }} pt/sack, {{ methodology.scoring.dst_int }} pts/INT, {{ methodology.scoring.dst_td }} pts/defensive TD, plus a points-allowed bonus (up to +{{ methodology.scoring.dst_pa_tiers[0][1] }} for a shutout, down to {{ methodology.scoring.dst_pa_tiers[-1][1] }} for 35+ allowed).

Projections — each position group (QB, RB, WR/TE combined, and DST) gets its own fitted formula: projected = intercept + a×(recent average) + b×(opponent's unit grade), fit by linear regression over every stored game since 2024 — no leakage, each game trained only on data strictly before it. Salaries are synthetic, not real FanDuel prices — within each position, a player's salary is their percentile rank by projection that week, mapped onto a price band ({% for pos, band in methodology.salary_bands.items() %}{{ pos }} ${{ '{:,}'.format(band[0]) }}–${{ '{:,}'.format(band[1]) }}{{ ', ' if not loop.last }}{% endfor %}). A player with no stored game history (true rookies, first game back from a long absence) has no projection and simply doesn't appear in the pool.

Optimizer — an exact integer program (not a greedy pick) selects the highest-scoring lineup under the ${{ '{:,}'.format(methodology.salary_cap) }} cap: {{ methodology.roster_requirements.QB }} QB, {{ methodology.roster_requirements.RB }} RB, {{ methodology.roster_requirements.WR }} WR, {{ methodology.roster_requirements.TE }} TE, 1 FLEX (RB/WR/TE), {{ methodology.roster_requirements.DST }} DST.

DST scoring covers sacks, interceptions, defensive touchdowns, and points allowed — fumble recoveries, safeties, and blocked kicks aren't tracked by the underlying data source and are left out.

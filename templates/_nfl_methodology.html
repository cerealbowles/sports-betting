How is this calculated?

Scoring (FanDuel's standard rules) — passing {{ methodology.scoring.pass_yd }} pt/yd, {{ methodology.scoring.pass_td }} pt/TD, {{ methodology.scoring.pass_int }} pt/INT; rushing & receiving {{ methodology.scoring.rush_yd }} pt/yd, {{ methodology.scoring.rush_td }} pt/TD, {{ methodology.scoring.reception }} pt/reception; fumbles lost {{ methodology.scoring.fumble_lost }} pts; return TDs {{ methodology.scoring.return_td }} pts. Team DST: {{ methodology.scoring.dst_sack }} pt/sack, {{ methodology.scoring.dst_int }} pts/INT, {{ methodology.scoring.dst_td }} pts/defensive TD, plus a points-allowed bonus (up to +{{ methodology.scoring.dst_pa_tiers[0][1] }} for a shutout, down to {{ methodology.scoring.dst_pa_tiers[-1][1] }} for 35+ allowed).

Projections — each position group (QB, RB, WR/TE combined, and DST) gets its own fitted formula: projected = intercept + a×(recent average) + b×(opponent's unit grade), fit by linear regression over every stored game since 2024 — no leakage, each game trained only on data strictly before it. RB adds a 3rd term, c×(recent rush attempts + targets per game) — the one extra feature that held up on two independent holdout tests (see nfl_model_challengers.py); the same idea tested for QB and WR/TE did not hold up on a second test and was left out there. Salaries are synthetic, not real FanDuel prices — within each position, a player's salary is their percentile rank by projection that week, mapped onto a price band ({% for pos, band in methodology.salary_bands.items() %}{{ pos }} ${{ '{:,}'.format(band[0]) }}–${{ '{:,}'.format(band[1]) }}{{ ', ' if not loop.last }}{% endfor %}). A player with no stored game history (true rookies, first game back from a long absence) has no projection and simply doesn't appear in the pool.

Optimizer — an exact integer program (not a greedy pick) selects the highest-scoring lineup under the ${{ '{:,}'.format(methodology.salary_cap) }} cap: {{ methodology.roster_requirements.QB }} QB, {{ methodology.roster_requirements.RB }} RB, {{ methodology.roster_requirements.WR }} WR, {{ methodology.roster_requirements.TE }} TE, {{ methodology.roster_requirements.FLEX }} FLEX (RB/WR/TE), {{ methodology.roster_requirements.DST }} DST.{% if methodology.stack_min %} Stacking is on: at least {{ methodology.stack_min }} WR/TE must share the QB's team, so their correlated upside moves together — the right lean for a large-field, top-heavy payout, not a cash game.{% endif %}

{% if methodology.max_low_tier is not none %}

Balance guard is on (experimental) — at most {{ methodology.max_low_tier }} of the lineup's non-DST players can fall below the {{ (methodology.balance_low_percentile * 100) | round | int }}th percentile of their position's own pool. Real hindsight-best lineups always turn out to need a mix, not pure stars-and-scrubs — but a direct backtest of this exact constraint (27 real completed weeks, scored against actual results) found it makes lineups WORSE at every setting that changes anything: real lineups look balanced only in hindsight, because some low-projection players happen to overperform that week — forcing MORE of them in blind, pre-game, with no signal for which ones will break out, just trades a good pick for a worse one. Left on here because you turned it on; off is the backtested-better default.

{% endif %}
